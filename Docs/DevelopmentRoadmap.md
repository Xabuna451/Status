# 상태창!! 개발 로드맵

> 작성일: 2026-08-23  
> 최종 갱신일: 2026-08-23  
> 버전: v0.1

## 1. 게임 정체성

모바일 세로형 증분 RPG. 플레이어는 **상태창에서 빌드를 구성**하고, 직접 조작 없이 자동전투로 균열 던전을 공략한다. 핵심 재미는 `빌드 변경 → 공략 결과 확인 → 장비/성장 획득 → 더 높은 균열 도전`이다.

## 2. 확정된 규칙

- 플랫폼: Android/iOS 우선, Unity 6 기반.
- 전투: 캐릭터 직접 조작 없음. 자동전투만 허용.
- 성장: 레벨/스탯/스킬/장비/강화/환생/계승.
- 오프라인 보상: 있음. 로컬 저장된 종료 시각을 기준으로 계산.
- 서사: 없음. 현대 판타지/균열/상태창 분위기만 사용.
- 장기 목표: 온라인 랭킹. 초기에는 싱글플레이 로컬 저장을 유지한다.
- 구조: UI, 런타임 전투, 콘텐츠 ScriptableObject, 저장 데이터를 분리하고 SOLID 원칙을 따른다.
- 씬 UI: `SampleScene` 하이라키의 일반 게임오브젝트를 직접 편집한다. 현재 캔버스는 프리팹 인스턴스가 아니다.

## 3. 현재 구현된 기반

- 5종 스탯, 스킬 노드, 장비/강화, 장비 드롭, 빌드 프리셋.
- 시간 제한 층형 던전, 보스, 적 특성, 위험 프로토콜, 전술 지침.
- 자동전투, 공략 기록, 숙련도, 업적, 환생/계승, 오프라인 보상, 로컬 저장.
- 모바일 uGUI 캔버스와 전투 피해 숫자/체력바/결과 문구의 초안.

## 4. 현재 확인된 문제

### P0 — 전투 UX

- 던전 입장과 자동 반복이 스크롤 아래에 있어 접근성이 낮다.
- 자동 반복 중 해제 수단이 고정 영역에 없고, 빌드 잠금과 섞여 플레이어가 갇힌다.
- 헌터/적 일러스트는 슬롯 구조가 불완전해 크기와 위치가 겹친다.
- 전투 아트 위에 너무 많은 텍스트가 올라가 가독성이 낮다.

### P1 — 화면 구조

- 전투 홈, 상태창, 던전 설정, 보상 결과가 한 화면에 섞여 있다.
- 전투용 일러스트와 배경 포함 세로 일러스트의 용도가 분리되지 않았다.

### P2 — 콘텐츠 체감

- 시스템은 있으나 장비 드롭/강화/보스 공략의 선택 결과가 화면에서 충분히 드러나지 않는다.
- 스테이지 목표, 다음 해금 목표, 수집 동기가 약하다.

## 5. 목표 화면 구조

```text
BattleHome (항상 보이는 홈)
 ├─ TopHUD: 현재 균열 / 최소 재화
 ├─ BattleArea: 배경 / HunterSlot / EnemySlot / HP / 피해 숫자
 ├─ BattleControlBar: 자동 반복 ON/OFF / 중지 / 입장
 └─ BottomNavigation: 성장 / 스킬 / 장비 / 균열 / 업적

StatusPanel (하단 메뉴를 눌렀을 때 열리는 별도 패널)
 ├─ 성장, 스킬, 장비, 균열 설정
 └─ 전투 중에는 빌드 변경만 잠금

ResultOverlay
 ├─ 공략 시간 / 획득 골드 / 경험치 / 장비
 └─ 다음 도전 또는 반복 계속
```

원칙: 전투 영역에는 전투 정보만 둔다. 상태창/설정/긴 설명은 별도 패널로 분리한다.

## 6. 개발 단계

| 단계 | 목표 | 완료 조건 |
|---|---|---|
| D0 | 현재 씬 안정화 | 콘솔 오류 0, 하이라키 참조 누락 0 |
| D1 | 전투 홈 재구성 | 고정 전투 제어 바, 전투/상태창 분리, 9:16 가독성 확보 |
| D2 | 자동 반복 안전장치 | 반복 OFF/중지 항상 가능, 공략 결과 확인 후 재입장 |
| D3 | 전투 비주얼 | HunterSlot/EnemySlot 분리, 배경, 피격/스킬/보스 연출 |
| D4 | 보상·성장 체감 | 결과 오버레이, 장비 드롭/희귀도/강화/다음 목표 표시 |
| D5 | 콘텐츠 확장 | 챕터, 보스별 빌드 요구, 장비 특성/세트, 수집 목표 |
| D6 | 모바일 완성도 | 실기기 UI, 저장/오프라인 보상, 튜토리얼 없는 첫 플레이 흐름 |
| D7 | 출시 준비 | 밸런스, 성능, Android/iOS 빌드, 스토어 자료 |
| D8 | 온라인 랭킹 | PlayFab 로그인, 서버 검증 점수, 시즌 리더보드 |

## 7. 온라인 랭킹 원칙

- 추천 백엔드: PlayFab.
- 클라이언트가 점수를 직접 기록하지 않는다.
- 던전 ID, 버전, 전투 결과, 시작/종료 정보로 서버 검증 후 리더보드에 기록한다.
- 첫 랭킹: 최고 균열 층, 보스 최고 공략 시간, 시즌 점수.
- D8 전까지는 온라인 기능이 현재 싱글플레이 핵심 개발을 방해하지 않게 분리한다.

## 8. 지시 방식

아래처럼 짧게 지시하면 해당 범위를 바로 구현한다.

- `D1 진행` — 전투 홈/상태창 화면 구조를 재구성한다.
- `D2 진행` — 자동 반복/중지 UX를 완성한다.
- `D3 진행` — 전투 슬롯, 배경, 연출을 만든다.
- `D4 진행` — 보상·장비 획득 체감을 만든다.
- `D5 진행` — 콘텐츠와 빌드 선택을 확장한다.
- `D6 진행` — 모바일 플레이 흐름과 저장을 검증한다.
- `D7 진행` — 출시 빌드 품질을 점검한다.
- `D8 설계` 또는 `D8 진행` — PlayFab 랭킹 구조를 설계하거나 연동한다.
- `현재 단계 진행` — 가장 우선순위 높은 미완료 단계를 이어서 개발한다.
- `문제 수정` — 현재 단계의 버그/가독성/참조 문제를 우선 해결한다.

## 9. 검증 기준

- Unity Console 오류/경고를 확인한다.
- Play Mode에서 전투 시작/클리어/실패/자동 반복 OFF를 검증한다.
- 9:16 모바일 해상도에서 텍스트 겹침과 조작 접근성을 확인한다.
- 저장 후 재실행과 오프라인 보상 계산을 확인한다.
- 기능 완료마다 씬 하이라키 참조와 직렬화 참조를 확인한다.
